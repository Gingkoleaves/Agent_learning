如何评估agent的输出结果是否正确和稳定、出错溯因

## LangSmith: [https://docs.smith.langchain.com/]

支持多种框架，使用sdk提供性能监控[token消耗]和评测轨迹[函数调用顺序、输入输出和错误]
支持框架的意思是，可以通过环境变量的设置启动插桩，在agent框架运行完毕后导出funciton调用记录

## Tau-bench

面向两个业务场景提供[数据库、api、业务规则、用户背景和期望结果]，通过agent接受模拟用户发出的需求，并观察运行结果[在数据库、api上的结果]，是否与ground-truth的符合业务规则的操作的结果相同

## OpenTelemetry for LLM/Agent [https://opentelemetry.io/docs/]

一套采集和发送运行数据的标准与工具，提供api和sdk工具，可用于导出agent、http服务、数据库、后台任务等多种服务的调用链和统计指标
可以手动插桩，即在action中加入with语句获取异常，并在真正业务代码前后加上记录语句

## 实践：可重复评测台

实现与运行入口见 [practice/README.md](practice/README.md)，实验结果见 [practice/report.md](practice/report.md)。

- 测例需先固定输入、用户脚本、初始数据库、事实/证据、动作规则和预期终态，再运行助手。答案与标签不能进入助手上下文。
- 每个 trial 创建独立数据库、模型计数和会话检查点；同题重复时不能继承上一次的成功写入或偏好更新。
- 自动判分必须读取真实终态。返回“已保存”或给出已有 task ID 都不证明写入成功，必须比较任务内容。
- 引用 ID 存在、原文包含摘录、摘录支持结论是三个不同条件；自由改写与跨资料比较仍需明确准则下的人工审查。
- 三次全成功比例为 `三次都成功的题数 / 完整运行三次的题数`；缺失 trial 不应悄悄算作成功。该作业指标不是 pass@k，也不代表完整 τ-bench 复现。
- OTel 的 trace_id 关联整题，parent span_id 关联模型与工具调用；故障事件、重试、实际输入输出和持久化结果共同用于溯因。
- 开发集用于发现并修复问题，holdout 在实现冻结后独立运行一次；两者分开报告。离线确定性夹具验证工程机制，不代表真实模型正确率或采样稳定性。
