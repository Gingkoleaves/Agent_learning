## MemGPT 补充实践（P3-06～10）

### 已完成的机制验证（2026-10-19）

实现：memory.py 的分层状态、持久化、成组FIFO移出、有限摘录摘要、六个原生工具、分页、heartbeat/yield、事件唤醒；solution.py 保留入口。VS Code 新增单步配置，说明见 MEMORY_WALKTHROUGH.md。

`python practice.py 3 run --mode memgpt --evaluate`：历史回归记录为15项通过（9项记忆机制、6项base）；原独立测试文件于2026-10-20清理，当前命令运行8项内置机制检查。包括真实子进程恢复、源消息验证、用户隔离、写入容量失败不提交、重复call_id不重复归档、成组移出、调用预算和timeout。

真实模型使用deepseek-chat，仅发送合成数据。第一次短记录演示：2次模型调用、2次工具调用、6279总token，约2.329秒。之后将答案置于80字符预览之外，单独验证依赖搜索结果的读取链：3次模型调用、4次工具调用、9458总token（9008输入+450输出），约3.562秒。两次都是机制演示，不是重复可靠性评测。

第二次证据：`evidence/memory_live_2026-10-19.json`。检索前prompt不含“青鹭”；模型实际调用working_context_update、recall_search、archival_search、memory_read，并回复正确代号，当前预算20、历史45，最终yield。记录中保留工具真实顺序、参数及usage。

四策略对照使用同一合成输入、11400 UTF-8字节输入上限；MemGPT计入工具schema成本。最终场景答案在原消息第一句之后：

两个预期失败注入：

1. 写入超长working context或负数时间预算：工具返回错误，存储不改变；正确方式是将长笔记归档或修正值。测试检查写入前后文件一致。
2. 单条消息超过固定区之外的输入容量：返回context_overflow、模型调用0次，不截断系统指令继续生成。测试覆盖该终态。
