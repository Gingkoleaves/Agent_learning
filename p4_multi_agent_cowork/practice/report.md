# P4 实验报告

## 实现与复现

本练习用 AutoGen Core 0.7.5 的 `RoutedAgent` / `SingleThreadedAgentRuntime` 实际投递消息。
三个角色有独立的 profile、observations、reflections；只有收到的内容进入角色上下文。
协作顺序由普通 Python 代码固定，模型负责提案、评议、反思和下一版安排。
没有模型自主路由、在线工具检索或分布式运行；这些不属于本次实现范围。

- 完成 P4-01～05；八个固定场景，三种模式，最多六轮修订、每组共用18次模型调用预算。
- 日期是固定测例日期，不以现实中的今天替换。
- 真实模型：DeepSeek `deepseek-chat`，每次最多900个输出 token；温度使用服务默认值，未锁模型快照。
- 数据：三份本地学习笔记的章节摘录，见 `data/corpus.jsonl` 的 source 和 line。
- `source_ids` 是消息 ID，`evidence_ids` 是文档段落 ID，二者不混用。
- 正常调用超时30秒；缺席故障将角色设为不回应，等待0.05秒后取消，按两人计划降级。
- 模型 API 不执行工具，工具调用次数均为0；通信消息数另外统计。
- 离线规则模型只用于协议验证，其 token usage 为 null，不能当成真实模型成绩。

```powershell
.\scripts\practice.ps1 4 run
.\scripts\practice.ps1 4 run --evaluate
.\scripts\practice.ps1 4 run --evaluate --provider deepseek
python -m unittest p4_multi_agent_cowork.practice.test_practice -v
```

以上平均值包含缺席和无交集场景。修复后整轮实际 usage：180921 tokens。

“场景通过”包括正确拒绝无交集场景、正确处理缺席；“完整计划”只计算三人讨论成功。
自动验证检查日期、时间交集、议程总长、角色分工、主题覆盖和引用存在性。
引用文本包含对应主题只是基础相关性检查，不是自然语言论断的完整语义评审。
每种模式每个场景只运行一次，不能从这点数据推出稳定的模型排名。

## 从真实失败定位修复

第一轮真实对照为19/24通过。
没有更改八个场景或期望状态来抬高成绩。修复只针对三类实际错误：

1. 模型把“交叉质疑与总结”写进固定枚举的 topic，导致下一版计划失效。
   明确要求 topic 只能用三个课程主题，把自由描述写入 preparation；下一版也做程序校验并允许一次反馈修订。
2. `later_start/multi_reflection` 中质疑者声称没有个人观察，返回空 source_ids。
   实际消息早已在 observations 中；明确提示这些就是观察，并列出可引用 ID。来源不合法时只允许一次修订。
3. `no_overlap/multi_reflection` 的初始回答把两个 JSON 对象拼到一起。
   在提示末尾强调当前阶段只返回一个对象；JSON 解析失败时反馈一次，仍计入18次预算。

## 两个故障案例

### 时间冲突

`time_conflict` 先形成19:00开始的草案，然后资料员通过 update 消息改为19:15可用。
程序发现原计划超出资料员时间范围，错误进入主持人的 observations，主持人重新生成符合19:15–20:00的计划。
这是通信实际改变行为的证据：不能在程序里偷偷替模型修改最终时间来宣称成功。

### 伪造引用

`forged_reference` 把第一项引用改为 `nonexistent:999`。
校验器查询本地语料，报告不存在；模型收到错误后改用真实段落 ID。
检查结果来自语料，模型或质疑者说“有效”都不能覆盖代码判断。

## 反思是否改变了后续行为

修复后普通场景的主持人反思提到：三段各20分钟占满一小时，同时承诺交叉讨论，安排需要更明确。
它建议各主题15分钟、留下15分钟讨论，并明确轮值引导。
当时的下一版输出采用了这个分配。重新运行时，可对照结果中的
`agents.host.reflections`、`plan`、`next_plan`，在 trace 中检查反思是否进入了模型输入。

这是当时观察到的行为变化，不是反思提高成功率的因果证明。
普通 multi 组也可能在第二次生成时改变措辞或时长，因此代码中的 changed_output 只表示 JSON 有变化。
本实验任务简单且有程序校验，单角色也能满足约束，多角色的额外通信未必带来收益。
每个角色都保留自己的 next_action；只有主持人的反思用于共同下一版计划，其他人的反思不自动共享。

## 验证与边界

九个 unittest 覆盖定向消息隔离、错误任务ID/收件人、引用与时间约束、超时降级、预算/轮数停止、
反思来源、非法JSON重试和下一版修订；离线24组合通过。
依赖安装后 `pip check` 无冲突。PowerShell 一键入口也已实际运行。

新运行的结果和轨迹写入 `artifacts/`，评测汇总位于 `artifacts/<provider>/evaluation.json`。
真实模型的 usage 来自接口返回，离线运行不产生真实 token 用量。
反思的来源检查不能证明推断正确；记忆仅覆盖本次实验，不做跨进程恢复。
后续若要研究自主协作，可把“固定谁发言”换成模型选择收件人；本章不再增加这个复杂度。
